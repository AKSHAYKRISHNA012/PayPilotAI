## 2. The 6-Stage Swarm Execution Architecture

Always follow this disciplined, multi-stage engineering pipeline:

### Stage 1: Ingestion & Compression (`Headroom` + `Ruflo`)
- Pass raw problem statements, government docs, and API specs through context compression to eliminate boilerplate tokens (60–90% reduction).
- Build a decentralized task graph breaking complex tasks into discrete, verifiable subtasks.

### Stage 2: Multi-Role Council (`GStack` + `Claude Council`)
Deliberate across virtual personas before writing code:
- **CEO / Product Strategist:** Value proposition, 10x differentiator, and user ROI.
- **Principal Systems Architect:** Microservices, schemas, data flow, deterministic algorithms.
- **Security Lead:** Zero-trust authentication enclave, secret hygiene, OWASP audit.
- **UI/UX Lead:** Anti-slop design, typography, spacing, responsive breakpoints, WCAG contrast.
- **QA Lead:** Edge-case failures, unbilled leaves, negative balances, stress scenarios.
- Probe assumptions with **REDTEAM** and **PREMORTEM** checks.

### Stage 3: Deep Synthesis (`Gemini 3.7 Flash High`)
- Evaluate council trade-offs and finalize System Architecture.
- Generate `implementation_plan.md`.
- Produce `DESIGN.md` enforcing color tokens, typography scales, and 8pt spatial grid.

### Stage 4: High-Velocity Code (`Claude-Code-Setup` + `21st`)
- Follow the **Explore ➔ Plan ➔ Code ➔ Commit** loop.
- Build clean, modern UI inspired by top products (Gusto, Rippling, Vensure) using `21st` components and `taste-design-system`.
- Strictly enforce **Backend Authentication** (zero client secrets).

### Stage 5: Dual Quality Audit (`Vercel Guidelines` + `Strix`)
- Run `web-design-guidelines` inspect for WCAG contrast and responsive breakpoints in `file:line` format.
- Run `playwright-cli` for headless end-to-end browser tests.
- When completing a major feature, ask: *"Are you ready for the Strix Security Audit and Penetration Test?"*

### Stage 6: Persistence & Learning (`Project Brain` + `Task Observer`)
- Write session context to `.brain/MAP.md`, `STATUS.md`, `HANDOFF.md`, and `DECISIONS.md`.
- Capture user feedback via `one-skill-to-rule-them-all` to continuously refine agent heuristics.

## 6. Zero-Trust Backend Auth & Strix Pentest Protocol

### Strict Backend Authentication Enclave
1. **Zero Client-Side Secrets Policy:** All authentication methods (JWT verification, OAuth2 flows, Session Cookies, API keys, Role-Based Access Control) MUST reside strictly in backend middleware and server-side routes.
2. **Never Expose Keys:** Client-side frontend bundles and public repositories will NEVER contain private API keys, database credentials, or secret encryption keys.
3. **Database Proxying:** All database queries and external APIs are accessed exclusively via secure backend proxy endpoints.
4. **Interactive Pentesting Trigger:** When completing a major feature, module, or full-stack application, pause and ask:
   > *"Are you ready for the Strix Security Audit and Penetration Test?"*
5. **Automated Remediation:** Dynamic endpoint fuzzing, SQL Injection checks, BOLA/IDOR verification, and automated PR diff generation.
